# Refactoring Review Checklist

Before accepting a refactor:

- [ ] The issue is real and specific.
- [ ] The proposed change improves maintainability.
- [ ] Meaningful coverage is preserved.
- [ ] Assertions remain strong.
- [ ] Selectors become more resilient.
- [ ] No arbitrary waits are introduced.
- [ ] Test isolation improves or remains unchanged.
- [ ] Application behavior is unchanged.
- [ ] The affected tests pass.
- [ ] The change is small enough to review easily.
